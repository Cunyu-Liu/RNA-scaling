```bash

bash resume_or_restore.sh --dry-run   # 先看分支判定（每臂 RESUME/RETRAIN/REBUILD）
```

## 5. 值守与监控恢复

```bash
# 服务器侧（resume_or_restore.sh 已自动做，手动版）：
crontab -l | sed 's/^#PAUSED#//' | crontab -    # 恢复 13 条值守 cron
cd ~/rna-sc && setsid nohup python -u -m rna_sc.watch_all >> /mnt/<你>/rna-sc/logs/watch_all.log 2>&1 < /dev/null &
```

- **DONE 自动收口链**：watch_all 检测 DONE 帧 → 自动逐层 probe（family split）→ 写 `eval/probe_results.jsonl`（正则已含 `_marscorpus|_rnacentral`）。
- **本地侧（你的 Mac）**：TRAE 两条定时任务当前是 Paused 状态——集群恢复后 **resume**：`RNA-LM 训练值守巡检`（每 30 分钟）与 `RNA-LM 每日晨报与推进决策`（每日 09:00，含每月 1 日竞争监控 M1-M4）。ssh 别名记得改新集群地址（`~/.ssh/config` 的 `Host A100`）。
- **新集群陷阱清单**（旧集群学费，逐条检查是否复现）：
  1. GPU6/7 型 cgroup 陷阱：新卡上先跑 `python -c "import torch; print(torch.cuda.get_device_properties(i).total_memory/1e9)"` 逐卡对照 nvidia-smi——**程序视角 ≠ smi 视角即陷阱**，禁用该卡；
  2. NFS 写截断：watcher 类脚本修改后**必须 scp 整文件**而非远程 sed/append（曾把 t437_gpu_watch.py 截成 4096 字节）；
  3. eval ledger 幽灵 claim：崩溃后 `status=running` 残留会永久 SKIP 评测——重跑前把该行改 `stale`；
  4. rw1/重加权任务只能手动 `train_s3_rw` 启动，永不进 supervisor/watcher；
  5. 共卡竞争：他人评测进程会动态挤显存（OOM 风口），大臂尽量独占或留 ≥1.5GB 余量。
