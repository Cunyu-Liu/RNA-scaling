1. 备份根全程只读；先在清单记录代码、bpRNA、split parquet、权重、tokenizer 的 SHA256。旧 evidence/JSONL 不覆盖，所有派生结果写项目新目录。
2. 远端仅在 `/home/cunyuliu/` 新建代码目录，例如 `rna_sc_p2_20261125`；权重、数据、缓存、日志、evidence 放 `/teams/HoulabData_1788502323/liucunyu/rna_sc_p2_20261125/`。`/home` 余量小，禁止放权重或特征缓存。
3. 不触碰 `/root/rnaft` 和其他课题目录，不 kill 任何进程，不修改既有任务状态。RTX5090 被其他课题占约 5.4GB，本项目可用约 27GB；每次启动前重新读 `nvidia-smi`，不能沿用旧余量。
4. 每个新适配脚本先跑最小 GPU smoke：模型在 CUDA、BF16 前向、tokenizer/MASK/logits 或输出 shape 正确、GPUGuard 无 fallback。CUDA 不可用或 CPU 静默降级立即停止并保留日志；smoke 不写正式账本。
5. 先落协议脚本哈希，再跑正式样本。正式运行不得临时减少序列、层、probe seeds 或把 family/random 切分互换。OOM 只能按各协议缩小 batch，数学协议不变。
6. 新证据先入原始 JSONL/CSV+manifest，再更新汇总/论文；probe seed、训练 seed、序列 bootstrap 分开命名。未完成任务按各文“失败降级”收缩主张，不写成已完成。

## 三、5090 并行建议

为给其他课题波动留余量，本项目计划显存总和**限制在约 20GB 内**，不是把 27GB 用满。并发只缩短墙钟时间，不减少总算力；GPU 利用率高时全部串行。

| 泳道 | 可连续任务 | 常驻估算 |
|---|---|---:|
| A（大模型） | P2.5 300M→650M，随后 P2.7 | 6–10GB |
| B（结构/外部） | P2.1 单单元，或 P2.3 单模型+randinit | 4–9GB |
| C（轻量，可选） | P2.2；或 P2.4 的 100M 单臂 | 2–6GB |

推荐 **A+B 两泳道**；仅当前两路实测峰值合计≤14GB 时加 C。不要同时跑 P2.5-650M、P2.4-650M、P2.3-giga 三个大模型；不要并发两个 P2.1-100M 单元只为赶进度。P2.3 的 trained/randinit 在同一进程顺序跑，避免条件 RNG 或权重实例混淆。

粗略总预算：串行约 5–10h，两泳道约 3–6h；若 P2.5 不缓存 states、逐单元重载，另增加 2–4h。实际以 smoke 和首单元日志为准，不能为符合估算改变验收样本量。
